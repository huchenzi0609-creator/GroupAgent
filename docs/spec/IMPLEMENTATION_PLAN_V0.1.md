# GroupAgent v0.1 开发任务与依赖

状态：任务分解基线，2026年11月16日按用户范围修订，不承诺固定交付日期。视频识别、视频生成、抽帧及音轨分析没有开发任务；语音生成／TTS暂缓，ASR保留。实际部署与验证见[目标机记录](../development/POT_2GB_VALIDATION.md)。

## 1 开发顺序

```mermaid
flowchart LR
    P0[验证实验与工程准备] --> P1[事件身份存储及策略]
    P1 --> P2[工作单执行器与工具网关]
    P2 --> P3[图片研究文档交付闭环]
    P3 --> P4[完整格式 记忆 调度 ASR]
    P4 --> P5[故障演练 灰度 与发布]
```

每个阶段交付可验证的工作流程。不要先堆出大量工具名称而没有结果验证和交付能力。排期在G0后，根据真实接口、资源和评估结果估算；不能直接沿用研究报告的粗略周数作为承诺。

## 2 验证实验

| Issue草案 | 目标 | 结果与退出条件 |
| --- | --- | --- |
| POC-01 微信消息和媒体 | 固定候选客户端与账号，核对事件ID、回声、增量流、图片/文件收发、语音输入、引用和撤回 | 能力矩阵、失败样例及真实手机验收；共用账号不能可靠去回声时改变账号方案 |
| POC-02 Harness组合 | 验证SDK工具循环、图像输入、运行中追加、取消、恢复、自定义工具和日志数据流 | 固定候选版本与配置；确认额外日志上传关闭；不借助未受约束的主机Shell冒充集成成功 |
| POC-03 隔离与权限 | 以合成凭证、恶意附件和越权成员验证路径、网络、插件及角色边界 | 明确可行的worker边界；越权样例失败即阻断采用 |

POC可以使用合成数据和独立环境，不需要先取得所有生产预算答案。生产账号、私密数据和付费调用仍需在已授权范围内使用。

## 4 第一条必须跑通的工作

选定测试群与合成课程资料，完成下列流程：

1. 成员无特殊前缀提出明确目标，并附图片或文档。
2. 系统正确认出请求者、讨论与允许范围，建立一次WorkOrder。
3. 执行器读取真实附件，检索公开资料，记录引用。
4. 生成DOCX及PDF，保存版本并进行结构和渲染检查。
5. 通过outbox发送文件，核对平台回执与手机端打开。
6. 中途追加要求、取消、崩溃恢复分别有重复实验；不会产生重复工作或重复交付。

这条闭环的完成不等于全版本完成。PPTX、Markdown、ASR输入、程序绘图和调度仍须通过自己的验收后才能达到G3；TTS暂缓，独立插画生成服务已按用户要求移出本版。

## 5 实施前需要冻结的配置

| 配置 | 当前状态 | 对什么工作构成阻塞 |
| --- | --- | --- |
| 生产账号是否独立 | 待owner选择，先兼容方案评估 | 生产E1及最终切换；不阻塞合成事件开发 |
| owner与角色绑定 | 使用合成ID开发，生产待配置 | 生产自动执行 |
| 日费用额度和供应商价格快照 | 未设实际金额 | 真实付费压测与生产启用 |
| 数据保留策略 | 主规格给出草案，待owner确认 | 实际群数据采集/迁移策略，不阻塞合成数据测试 |
| Harness运行组合与版本 | 优先候选，待POC-02 | 具体适配器冻结；不阻塞EnginePort契约 |
| worker规格 | 待POC-04测量 | 生产并发与性能承诺 |
| 文档代表样本 | 先建立合成样本，再补经授权模板 | 高保真需求最终冻结 |

这些待决策项集中管理，不要求在每一个普通任务上重复询问。确认结果写入配置/ADR和spec变更记录。

## 6 变更与完成定义

实现每个issue时，关联主规格要求ID和验收用例ID。新增能力、放宽权限、改变收费或数据保留范围，以及重新引入视频，都需要明确的规格变更，而不是隐藏在某个PR中。

每项交付包含代码、适当测试、契约与用户行为说明、观测点、迁移/回滚影响及证据。某个供应商不可用时写BLOCKED或采用已评审替代，不降低完成定义来掩盖失败。

规格文档完成标准为：契约可审阅、需求到验收可追踪、视频排除与TTS暂缓范围一致、配置及例子可解析、无秘密或真实群数据进入Git。实际服务切换与验收结果另行记录，不能以文档完成代替运行验证。
