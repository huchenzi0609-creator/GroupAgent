## 实现范围

前后台现在共用 `AgentKernel`，模型与工具调度由锁定的 LangChain `create_agent` / LangGraph 承担，各自保留会话上下文。外围服务负责租约、资源准入、来源授权、成果校验和交付事实。旧 Scoped 自写循环、原生 Harness worker/relay 和前台 Decision-JSON-first 路径已经退出；兼容导入不启动另一套执行器。

检查点保留图调度状态、待提交写入和工具幂等记录。工具错误作为同一图内的观察供模型修正；资源让出会持久排队，控制进程重启后以新的 fencing token 恢复。用户手动暂停、取消和权限撤回仍生效。未知外部效果先核对原回执，不能靠清空状态重复执行。

前台通过 `start_work`、`update_work`、`control_work` 和任务事实工具操作同一业务状态，事务先提交，再将真实结果交给模型回答。聊天可直接生成自然回复，不再强制先输出业务 JSON。工具授权来自可信角色、来源及群功能；语义能力计划只影响最初展示哪些已授权工具。

本轮同时修复了实模暴露的检查点 NUL 编码、数量上下界、错误处置、文档准备阶段效果判定，以及图下来源说明。取消的金额、token 和目标累计步数预算没有重新引入；计费账本、单次调用资源约束和异常退避继续保留。

服务器持续运行检查还要求维护通道隔离：压缩、到期处理、删除证明与归档扫描放入单并发执行通道，异步模型和通道回调留在所属事件循环。前台锁等待使用有界、可重试的资源等待；新消息请求维护在安全作业边界让出。停机排空真正的工作线程及回调后才关闭资源、释放租约，期间心跳继续续租。没有通过延长租约或关闭租约检查规避阻塞。

## 数据与服务器切换

本次只更新 `test_2` 的 Pot 控制器和专用 Docker 代理，保留原微信客户端、PostgreSQL、PM2 小游戏和群数据。发布前固定源码、锁文件与镜像，验证备份后才交接配置、替换完整代码目录并启动唯一发送者。失败回退保留数据库与文件，不恢复旧快照覆盖新记录。

旧隐私队列混合了本地删除与微信缓存删除，导致备份被永久未完成的上游义务阻塞。本轮将二者的事实分开：只有可信控制路径实际完成文件清理和数据库脱敏，并提供与当前作业、来源和派生数据精确绑定的证明，才允许将本地状态归档。上游清理不受支持的义务继续保持待办，不标记完成。无证明、证明过期、清理失败或活跃租约均阻止发布。

实际维护另暴露了证明的排序缺陷：同一事件下的多条媒体记录只按事件 ID 排序，重叠的幂等清理可以改变物理行顺序，使内容完全相同的证明失效。本地真实 PostgreSQL 已复现“修复前失败、修复后通过”，改为完整主键排序；未知、过期或错误证明仍被拒绝。服务器当时 3 项不匹配均仅涉及 scope 摘要。最终版本规范清理实测 197 项当前证明全部匹配、0 项缺失，2 批后通过，外部擦除义务仍保持待办。

维护隔离版 source08 已完成 7,454,929 字节新备份验证和单发送者交接，实际镜像 `sha256:9eaf727084bde014521490d627b01e12f6cc31fde2fe3eeeca8f932d473c5795`，安装源码摘要与冻结清单一致，授权 revision=30，金额政策 revision=4 且日/总限额均为空、未冻结。真实维护中同一容器和应用租约连续稳定 88.3 秒后才发送测试输入；随后任务及回声观察期间均未发生重启。

## 尚未达到的性能目标

按原生事件时间到微信接受回执计算，任务承接首次回复约 30.14 秒，后台期间追问约 17.87 秒；按入库开始计算分别为 27.41 秒、12.01 秒，均没有达到 10 秒目标。配置为 `deepseek-flash` 且 thinking 关闭；前者两次模型调用共 5.21 秒，后者一次约 4.10 秒。主要差额位于模型计时以外的主机处理及发送，其中任务入库至首次模型预留约 11.27 秒，两例模型结算至出队均约 3.05 秒，出队至微信接受约 2.70–3.50 秒。

现有证据不支持“仍然卡死”、推理模式错误或任务进度见证反复失效。成功处理会删除重试行，不能凭当前重试表为空排除此前短暂资源等待。准确定位函数级热点仍需上下文构造、快照验证和发送阶段的细分计时；本轮未凭猜测增加规则或重启正在执行真人工作的稳定服务。此项保持未通过，不以普通承接话术冒充有用结果已经完成。
