版本：v0.1 Draft

日期：2026年11月14日（按用户最新范围修订）

目标：面向普通微信群的通用协作智能体首个可发布版本。本文版本号属于规格文档，不表示功能已经实现。

本规格承接已评估的[开发前报告](PRE_SPEC_REPORT.zh-CN.md)，并以用户最新要求为准。**视频识别不在当前开发计划内**，不分配实现任务、供应商选型、性能预算或上线验收指标；后续需要重新立项才能纳入。

## 2 产品目标

机器人应像一个能做事的小组协作者：理解成员讨论，在合适的时候参与；接到明确目标后，自主找资料、分析图片和文件、执行工作、检查结果，并把可用产物交付到群里。执行长任务时，成员仍可与它交流、改变方向、暂停或取消。

首版重点是一个授权群、一个机器人身份、多个真实成员。架构必须支持群隔离，首版不提供公开注册、多租户计费或无限制开放代理服务。

产品必须区分三个决定：**是否理解并保存上下文、是否发言、是否执行操作**。观察群聊不等于对每条消息回复，自然参与也不等于把所有讨论当作已授权指令。

### 2.1 首版范围

| 能力 | v1首个可发布版本的范围 | 分阶段实现说明 |
| --- | --- | --- |
| 群聊交互 | 无需特殊前缀，自然提问、讨论接续、主动补充、安静与停止 | 核心必选 |
| 文本与图片 | 文本、截图、图表、作业照片、引用图片的关联与分析 | 首条端到端闭环必选 |
| 语音 | 群语音转写、以文字回答；按明确请求生成短语音回复 | 仍在当前计划内，后于图片交付；未完成不得称多模态验收完毕 |
| 文件 | .md、.docx、.pdf、.pptx读取、检索、声明范围内的编辑、生成和交付 | 四种格式均是首版发布要求，按复杂度逐步实现 |
| 联网 | 自主搜索、打开网页、来源核对、整理与引用；必要时受控浏览器操作 | 核心必选 |
| 执行 | 受约束工具循环、后台工作、预算、取消、恢复和验证 | 核心必选 |
| 交付 | 真实文档、图表、图片，按需短语音；内容校验、版本与发送回执 | 核心必选 |
| 记忆 | 连续对话、自动摘要、检索、事实与决策、成员ID、长期分工 | 核心必选 |
| 调度 | 自然语言一次性和周期工作、有限事件触发、修改／暂停／取消 | 核心必选 |
| 扩展 | 工具注册、允许清单、独立worker、可替换执行器 | 核心必选；不是无限插件安装权限 |

### 2.2 明确不做

- 视频内容理解、抽帧、视频音轨分析、视频生成及实时视频流。
- 独立插画生成服务或外部文本生成图片API；现有实验性适配代码不代表本版启用或必须配置的能力。
- 实时语音通话、数字人、声纹识别和身份推断；语音消息处理属于首版。
- 任意格式／任意网站的无条件自动处理、无限长任务、无限并发。
- 自动付款、下单、修改服务器或账号安全配置、绕过验证码或登录限制。
- 默认访问其他群、私聊、服务器全盘文件或其他应用账号。
- 自动提交课程作业、群外发布或代表成员作正式承诺；这些需要未来明确的授权能力。
- 全功能Office复刻，或任意PDF、复杂PPT动画与嵌入对象的无损编辑承诺。

接收到视频消息时，只保存必要的消息元数据和“不支持视频分析”状态，不下载视频、抽取封面进行分析或提取音轨来变相实现视频识别。仅当成员明确询问视频内容时，说明暂不支持并建议提供截图或文字；否则保持静默。

## 3 用户、身份与授权

### 3.1 身份规则 ID-001

- 身份主键是通道提供的稳定微信成员ID；昵称不能作为主键或权限依据。
- 名单在机器人启动时同步一次，不做周期全量刷新。群负责人可明确要求刷新；未知成员先按ID占位，不强迫逐一报到。
- 显示姓名只使用群昵称字段；群昵称缺失时，采用负责人明确确认并与ID绑定的姓名例外，或显示“群昵称待补充”。不得将个人微信昵称、私有备注或模型猜测当作真名。
- 名单同步失败不清空既有身份和历史任务，也不能断言成员退群。可靠的离群事件可立即撤销该成员权限，不需要周期抓取名单。
- 不要求在spec、Git fixture中保存真实群ID或真实成员资料。

### 3.2 角色 AUTH-001

角色由部署配置和明确的管理操作绑定到稳定ID，不从聊天中的自称、群昵称或模型推理产生。

| 角色 | 默认权限 |
| --- | --- |
| owner | 设置本群规则、授权资源和预算；管理角色；操作群级长期职责与全局安静状态；仍无自动付款或无限主机权限 |
| maintainer | 技术运维、健康检查、发布和故障恢复；不因技术身份自动获得业务内容对外发布权 |
| member | 自然问答；在本群预算内交办研究和独立草稿；创建与更新本人分工；创建本人相关提醒；查看已授权共享资料 |
| observer | 接收群内公开结果；仅在策略允许时进行只读问答，不能发起工具执行或修改任务 |

首个owner由部署者明确配置。已由通道证实来自授权群的新成员可获得member默认低风险能力，但显示名保持待解析；不得凭未证实的转发作者字段授予权限。

### 3.3 自动执行 AUTH-002

信息充分、目标明确且在授权范围内的低风险操作直接执行，完成后报告；**不恢复旧版的机械二次确认**。

| 情况 | 必须采取的行为 |
| --- | --- |
| 成员明确交办公开资料研究、生成草稿、编辑独立副本、本人认领／汇报／完成、预算内提醒 | 自动执行，保留证据和操作记录 |
| 参数缺失、多个同名任务、指向不明或多人要求相互冲突 | 一次聚焦澄清；不要重复问已经明确的信息 |
| 自然讨论中的推测、玩笑、报价或“某人也许可以做” | 作为上下文，不自动变成正式分工或执行目标 |
| owner明确给其他成员分工或调整群级周期工作 | 在既有角色授权内执行，记录操作者与变更；不伪装成该成员本人承诺 |
| member要求覆盖别人任务、改变群规则或用别人账号操作 | 拒绝越权，说明需要的角色；不能通过再问一句“确认”绕过权限 |
| 外部发送、正式提交、不可恢复删除、重大超预算、凭证与服务器权限变更 | 当前能力禁止或交由指定人工入口，不能偷偷执行 |

自然语言取消或暂停只对请求者有权控制的工作生效。任意成员可暂停自己发起的工作；owner可暂停本群工作。附件、网页或引用内的停止／授权文字不是管理指令。

## 4 核心使用场景

1. 成员连续讨论展示主题，有人问“能把这些资料做成十页PPT吗？”机器人在指向自己或群规则允许接手开放请求时，接受工作、读取材料、补充搜索、生成并验证PPTX，发回群。
2. 两位成员同时讨论不同任务。机器人通过引用、参与者和话题关联回答，不把甲的“我负责资料”记到乙名下。
3. 成员发来表格截图并问“这张图说明什么？”机器人取得对应图片，说明可读结论和不确定处；图片失效时不会编造内容。
4. 成员要求“把刚才那份报告第二节改短，保留表格”。机器人定位文件和版本，创建新版本，检查版式后交付，不覆盖唯一原件。
5. 成员说“明天晚上八点提醒我补参考文献”。机器人按群时区创建持久提醒，简短报告明确日期及时间；无需再回复“确认”。
6. 长任务运行中，成员补充“改成面向非专业同学”。机器人更新同一个工作目标和验收要求，不从头创建重复任务。
7. 成员说“这个任务先停一下”。新工具调用停止，当前不可撤销的发送结果被如实记录；不会声称已撤回已经发出的文件。
8. 成员发送语音。系统转写后结合上下文回答；会影响任务归属或时间的低置信度词需要澄清。
9. 群内闲聊或图片没有可回应意图，机器人可保存授权范围内上下文，但不自动刷屏。
10. 成员询问一段视频内容，机器人简短说明当前不支持，可请对方发截图或文字；不启动视频分析流程。

## 5 群聊参与与语言

### CHAT-001 自然参与

正常使用不得要求“/组长”、固定菜单、任务编号或特殊格式。支持这些作为可选快捷与排障入口，但不以此限制自然语言能力。

每批事件必须得到可审计的参与决定：ignore、observe、reply、clarify、start_work、update_work、control_work之一。参与决定不直接执行副作用；执行前仍需通过工具策略。

以下情况优先响应：直接叫机器人、回复其消息、询问它正在处理的任务、明确的结果请求、可解决的未回答问题。明确叫另一个人的请求，不应被抢走。全群开放请求只有在本群预授权范围内且意图足够清楚时才可自动接手。

对普通讨论主动补充前，必须判断新内容的实际价值、是否已有成员回答、是否会打断正在进行的交流。低置信度可以静默；不能把“无特殊指令”实现成每条消息必答。

### CHAT-002 多人、多话题与接续

消息首先关联原生引用及工作单，再结合主题、参与者和时间窗口。模型判断与关联证据必须记录。关联不唯一且将引起写操作时，先澄清；只读回答可说明采用的上下文。

同一工作只允许一个主执行者，允许多个订阅讨论。不同工作有独立执行会话、文件范围与预算。新消息可追加到正在运行的工作，但已经完成的外部副作用不能被新的要求自动“抹掉”。

### CHAT-003 节奏与长度

- 移除200字硬截断，包括生成端和发送端。不得切掉正文后假装完整回答。
- 日常默认1—3个短句；复杂问题按需求展开，优先群内摘要加真实文件。长消息分段应保持顺序、完整性及所属工作。
- 默认按2秒空闲窗口合并相邻讨论，最长等待5秒。控制指令不进入普通批次等待。
- 自发插话默认最多每群10分钟2次；被直接询问、必需澄清、取消结果及交付不占此配额。超出配额的建议合并或静默，不丢弃明确任务。
- 进度更新仅在有意义变化、阻塞或交付时发送，普通进度默认间隔不少于60秒。长任务可先发一次简短接单信息，不逐步播报内部推理。
- 沿用简短机器人身份标识，或在独立机器人账号下通过身份展示。拟人化不等于伪装真人经历或把预计结果说成已完成。

以上节奏数值是初版配置默认值，需要shadow回放校准；不得绕过明确的静默要求。

### CHAT-004 安静、暂停与停止

支持“先别插话”“十分钟后再聊”“继续”“停止这个任务”“以后不用每天提醒”等自然表达。必须区分停止发言、暂停某个工作、取消定时规则与关闭本群处理。

默认不设置固定夜间静默时段，避免替用户作息做决定；owner可自然语言配置。静默期间允许直接回应明确呼叫，但禁止自发讨论补充；到期提醒按静默策略延后或只保留一条汇总，不能无限补发。

## 6 图片 语音与附件

### MEDIA-001 图片

图片必须关联真实消息、发送者、引用关系与附件ID。先下载可用媒体，再校验实际格式、大小和哈希；保留原图引用，按需进行OCR和视觉推理。不得仅凭文件名、缩略图标签或“图片”占位符回答图中内容。

支持JPEG、PNG、WebP和GIF静态首帧。GIF首帧分析必须标记为静态视图，不声称理解整个动画。多图需要保留顺序和对应消息，避免把甲的图片用于回答乙的另一项任务。

附件不可用、已过期、被撤回、格式不支持或超限必须形成明确状态。主动询问时说明具体限制；未经询问的失败不应频繁打扰全群。

### MEDIA-002 语音

语音消息经转写后进入同样的讨论／执行策略，转写必须保留消息来源。对姓名、数字、截止时间等关键低置信度内容先澄清，不能据猜测执行。

默认以文字回复；用户明确要求朗读或语音答复时才调用TTS。优先短语音，不默认克隆任何人的声音。语音生成与发送必须有产物记录和回执；超出通道限制时改用文本或可用音频附件并说明。

### MEDIA-003 视频排除

视频消息以unsupported_video事件表示；不创建视觉、OCR、ASR或视频worker任务，不进入当前图像理解验收集，也不为未来视频能力预先购买或安装专用服务。

### 附件默认限制 LIMIT-001

以下是产品自身的初版准入上限，不是模型或微信的最大承诺；最终有效上限取产品、平台和供应商限制的最小值。

| 类型 | 初版默认上限 |
| --- | --- |
| 图片 | 每张15MiB、解码后40MP；同一次视觉任务最多10张 |
| Markdown/文本 | 2MiB；按UTF-8读取，无法识别编码时澄清或显式转换 |
| DOCX/PDF/PPTX | 每文件30MiB；PDF及DOCX渲染最多200页，PPTX最多100页 |
| 语音消息 | 按实际通道上限；普通音频文件最多10分钟、25MiB |
| 单次工作文件集合 | 最多20个输入文件、总计100MiB；必要时拆成用户可见的子任务 |
| 单worker工作区 | 默认512MiB硬限，不含只读基础镜像；超限暂停，不删除原件 |
| 单个交付文件 | 默认25MiB；平台上限更低时遵循平台限制 |

上限内也可能因内容复杂度达到时间或费用预算；必须报告未处理范围，不能静默只读开头后宣称完整处理。

## 7 文件浏览 编辑与交付

### FILE-001 文件对象与浏览

所有文件通过内部file_id与artifact_version_id访问。模型只得到有权限的文件清单，不接收宿主任意路径。支持按名称、类型、项目、发送者、版本与内容检索；结果包含来源消息或生成工作、版本和可用状态。

同名文件不得自动覆盖。用户说“刚才那份”时，优先使用直接引用或当前讨论关联；多份候选可能导致不同修改时，必须问清楚。

### FILE-002 格式能力

| 格式 | 必须支持 | 明确边界 |
| --- | --- | --- |
| .md | 全文／分块读取、搜索、局部修改、创建 | 保存转换信息，不承诺任意编码无损 |
| .docx | 常用段落、标题、表格、图片、样式、模板生成、定点编辑 | 高级嵌入对象、复杂修订等先做能力检查，不静默破坏 |
| .pdf | 文本抽取、页面图像、扫描OCR、页码引用；页面组合、标注、表单或明确重建输出 | 不把任意PDF重排声称为原位无损编辑；原件保留 |
| .pptx | 幻灯片文字、图片、表格、常用图表及模板；新增、调整和定点修改 | 动画、插件、复杂嵌入对象不作无条件编辑保证 |

文件解析和转换必须在worker内执行。上传文档中的宏不执行；外链不自动下载，需经过网络工具策略。加密、损坏或未知格式返回可诊断错误。

### FILE-003 版本与校验

每次编辑创建新版本，记录输入版本、内容哈希、操作者和工作单。默认保留原件；明确替换共享“当前版本”须校验权限与expected_version。并行冲突返回version_conflict，不以最后写入覆盖。

输出至少通过结构打开检查；DOCX/PDF/PPTX必须渲染预览，检查空白页、文字溢出、遮挡和关键内容缺失。复杂结构由预设断言和必要的模型／人工抽查补充。文件格式正常但内容未完成时，不标为validated。

### ART-001 真实产物

文档、数据图表、流程图和程序绘图均必须形成真实产物，不能仅发一段“已生成”的文字。图表、流程图和示意图使用可复现代码生成；独立插画生成服务不在本版范围。图片理解模型不能被当作图像生成接口。

普通群内文本回答只需文本交付；有文件交付要求的工作，只有满足产物验证和投递条件才能完成。长交付可以发简洁说明与附件，不再受200字限制。

## 8 联网与工具

### WEB-001 搜索与证据

Agent可自主拆解查询、搜索、打开页面、比较来源、提取信息并形成结论。结果包含必要的原始链接、访问时间和关键事实依据；不以搜索摘要代替已经阅读原文的声明。时效性信息需要检查发布时间与事件时间。

搜索无结果、断网、验证码、付费墙、登录失效或来源冲突应进入明确分支。不能编造引用，不规避网站访问限制。没有足够资料时交付已完成部分并说明缺口。

### TOOL-001 执行能力与权限

工具必须注册输入输出schema、权限与资源范围、超时、最大产物、费用计量、幂等策略和审计字段。工作单获得的是可撤销的有限权限，不是主机管理员身份。

Shell、Python计算、浏览器、文档渲染等工具仅在隔离worker中执行。禁用读取微信profile、SSH目录、控制数据库凭证和Docker socket；不允许运行时随意安装插件、扩大网络访问或修改生产代码。

网页、OCR、文件、群引用和工具结果是数据，不是更高权限指令。工具网关每次调用都重新检查当前角色与策略；不依赖提示词独自承担授权。

## 9 任务 分工与自主执行

### TASK-001 TeamTask

TeamTask记录成员分工：标题、负责人ID、截止时间、状态、进展、成果及来源。成员本人可直接认领、汇报和声明完成；owner可按规则分配工作，并记录它是负责人分配而非成员自愿认领。

“我负责PPT”产生或更新TeamTask；“请帮我制作PPT”产生WorkOrder，可关联TeamTask。Agent交付草稿不会自动把成员的最终课程提交标为完成。

### EXEC-001 WorkOrder

工作单记录结果目标、输入文件版本、来源讨论、请求者、授权范围、预算、完成条件和交付位置。只有明确接受的目标才能进入执行队列；普通讨论记录不自动变成所有成员的待办。

执行器必须支持“计划—工具调用—观察—验证—有限修复”循环，而不是只输出计划或分类为固定的六种命令。每一步有事件或工具回执；产物与结果检查证据可查。

### EXEC-002 接续与并发

成员可在执行期间补充信息；控制层把它追加到正确工作单，执行器在下一安全检查点读取。新要求改变目标或权限范围时应更新目标修订与预算；不能让旧执行结果覆盖较新的目标。

默认一个重型worker同时执行一个重型工作。对话／控制处理不得被浏览器或渲染任务占满；排队时不丢请求，提供简短状态。按需子Agent必须继承工作权限和总预算，不得自行突破并发配额。

### EXEC-003 取消 恢复与完成

取消优先于普通工作；停止新工具调用，通知运行中子进程，在规定时间后终止可终止进程。已提交外部操作需查询结果并记录，不声称取消等于撤销。

重启后从持久状态与副作用账本恢复，而不是重新执行整个提示。未知发送结果先核对回执；非幂等操作结果不明时进入待核对状态，不自动重复。

工作单completed表示：必要步骤已完成、验收条件通过、必需产物已验证、要求的群内投递获得平台接受回执。它不表示成员已阅读或满意；这些另行记录。

## 10 记忆

### MEM-001 分层与溯源

保留原始事件索引、最近讨论、滚动摘要、结构化事实／决策、TeamTask和成员偏好。事实包含来源、说话人、时间、范围与可信状态。原文和已确认业务记录不能被摘要覆盖。

模型回答可检索相关主题、成员、工作单和文件。原文过长时采用分块与检索，不能因只看最近窗口而声称知道全部历史。记忆缺口或指代冲突要明确表现。

### MEM-002 压缩与纠错

按模型上下文预算触发压缩，不按“永远固定16条”作为唯一规则。成功写入摘要和checkpoint后再推进游标；失败保留原始记录。摘要标注来源范围和未覆盖内容。

成员可以自然语言更正自己提供的事实；涉及他人任务或群规则时按角色授权。更正使旧事实失效但留下审计链。历史中的确认不能授权新的操作，撤回或删除必须向索引和摘要传播失效标记。

## 11 定时工作

### SCHED-001 创建与管理

支持一次性、固定间隔、每日、每周和明确日期时间；高级cron/RRULE仅通过受校验的规则接口，不执行任意字符串。有限事件触发包括：相关工作完成、已授权资料出现、任务将到期等预定义事件，不开放任意持续网页爬取表达式。

创建后简短复述明确时区、下一次执行和有效范围，不要求无意义的再次确认。缺少结束日期不必总追问：一次性任务自结束；周期任务采用默认30天有效期并告知，除非用户已明确其他期限。

支持列出、修改、立即运行、暂停、恢复、取消；有revision控制，避免并发修改互相覆盖。修改规则不改写历史发生记录。

### SCHED-002 生命周期

默认时区Asia/Shanghai，存储UTC时刻及IANA时区。默认停机补跑策略为latest_only：一次性过期任务在24小时宽限内补一次，超过宽限只报告错过；周期任务最多补最近一次，不逐条轰炸。

同一规则前一执行未结束时，默认合并后续触发；下一次只保留一个待处理发生记录。每条规则默认最多每小时一次、每群最多10个活动规则；超过限制需要owner调整策略。

已授权职责中的有限跟进可以由Agent自主创建，但必须有到期时间、可见记录、预算和取消入口。定时任务触发不得直接无限创建更多定时任务；派生规则需同一授权范围并通过配额与循环检测。

## 12 资源 费用与数据保留

### BUDGET-001 默认执行预算

每个工作默认最多24轮模型调用、200000个累计输入输出token、60次工具调用、20分钟活动执行时间、最多2个子Agent且最多1个重型执行并发。单工具默认60秒，浏览器90秒，文档渲染180秒。等待用户输入和排队不消耗活动时间，但保留总截止期限。

在下一步可能超出剩余预算时暂停，不依赖结束后才发现超额。能估计的付费调用先预留，再按实际结算；重试也计入费用。单群每日费用上限是生产必填配置，金额尚待owner确定，测试可使用明确标记的虚拟额度。

### DATA-001 保留与授权

初版草案默认：原始群消息保留30天，原始附件30天，生成产物90天，操作审计90天，备份7天；任务、已登记身份、明确决策与必要成果可长期保留，直到项目归档或有权限的删除请求。上述保留策略必须在生产启用前由owner确认，不默默套用到旧数据。

原始数据到期不应通过无限摘要绕过删除：摘要中的普通聊天细节随其保留策略失效，只保留被明确提升为项目事实或决策的内容及最小证据。已撤回／删除的敏感内容从在线检索中及时排除，备份按到期轮换清理。

模型调用只传当前任务所需、已授权群的数据；不得跨群自动共享。公开搜索查询应省去不必要的成员姓名、私密任务和凭证。日志不记录API密钥、登录二维码内容或完整私密附件。

## 13 系统与接口基线

采用独立ChannelAdapter、ConversationCoordinator、WorkService、EnginePort、ToolGateway、ArtifactService、MemoryService、Scheduler和DeliveryService边界。控制层与worker分进程，业务状态不能只存在于Harness上下文中。

候选执行器为DeepSeek Harness SDK／插件组合，运行组合、版本、日志贡献关闭与隔离效果经过E2验证后才冻结。正式业务存储采用PostgreSQL契约，集成测试使用同类数据库；旧SQLite仅作迁移输入或离线fixture，不并行维持两套生产语义。

文件存储通过ArtifactStore抽象访问，首版可用受控文件存储或对象存储；接口必须具有内容哈希、权限、版本和原子发布语义。第一版不要求Redis或独立向量数据库。

详细对象、端口、状态机、错误与幂等规则以[技术契约](spec/TECHNICAL_CONTRACTS_V0.1.md)为准。所有可替换实现必须通过相同契约测试。

## 14 非功能要求与发布

- REL-001：消息接入、对话控制、执行、调度与投递故障可隔离。单个不确定投递不得阻塞整个群。
- REL-002：关键状态提交后才确认消费；有版本迁移、备份、恢复和单一生产发送者机制。
- OBS-001：trace_id贯穿事件、工作、工具、产物和投递；显示健康、队列、耗时、错误、费用、丢失／重复事件和待人工处理项。
- PERF-001：从服务持久接收事件到回复进入outbox，长任务接单信息P95≤5秒，普通短回答P95≤20秒；平台运输延迟另计。控制指令入库与阻止新工具调用P95≤2秒，可终止进程默认在10秒宽限后终止。
- SEC-001：worker无主机管理员权限、微信凭证或Docker socket；网络与路径范围由代码控制，非提示词控制。
- GOV-001：每个发布记录应用commit、镜像digest、引擎／通道／模型／提示词／schema版本及验收证据。生产不接受未提交的热改。
- OPS-001：支持shadow、测试群、小范围工具开放与生产灰度；启动前验证配置，账号失效时暂停相关发送并告警。

这些是目标，不是当前测量值。具体测试分母、场景和上线阻断规则见[验收规格](spec/ACCEPTANCE_V0.1.md)。
