# 0003：聚焦会话、统一控制与可复用证据

日期：2026-11-16。状态：实现与验收中。适用分支：`refactor/pot-conversation-core`。

## 问题与目标

控制对象、讨论上下文和出站发言分别存在多套判断：快路查全局工作，模型查公开工作，诊断又猜最新工作。暂停项和旧聊天在普通问候前就被加载。静默既依赖模型的`directness`，又允许旧普通回复继续发送。新目标可能被接到一个无法恢复的旧工作上，随后状态文字却声称正在执行。

这些问题需要边界一致，而不是给提示词补更多特例。本轮保留已经验证的身份、来源、角色、租约、撤回、幂等与隔离机制，重整解释和编排。

## 决策

### 1. 解释与执行分开

模型提出`WorkSelector`，其中状态、请求者过滤`requester_scope`、单个／全部和排除项必须保留。`resolve_work_selection`统一解析焦点、引用、明确ID与条件查询。过滤条件和修改权限分开：负责人可以选择不同请求者的明确集合，普通成员只能修改最终集合中自己的工作。后端冻结真实ID、状态和版本，提交时重新核对；不能把复数选择替换成一个方便的旧工作。

`query_work`由后端渲染实际状态，避免模型根据旧回复自行声称工作正在执行。旧的独立HTTP路由器移除，生产入口只使用同一模型适配与候选校验链路。

即时事务使用`command`，普通发言使用`reply`；模型不同时编造操作结果。任务事实与发言对象是两个维度：“由我准备”这类明确认领可以静默记录，不因没有点名机器人而丢弃，也不据此插入真人对话。操作授权和来源核对保持不变。

面向模型的协议使用按`kind`区分的封闭对象分支，不复用持久化兼容对象中所有可空字段。工作必须有非空目标，普通聊天只生成回复字段，操作结果由后端生成；身份元数据与交付正文指令分开。使用标准JSON Schema校验器验证分支和实际发现的无效候选，同时保留旧记录读取与原有来源、角色和引用校验。

可信真人收件人只约束发言方向，不再提前截断业务声明解释。缓存名单的群昵称与在群状态分开：可信唯一昵称仍可识别收件人，明确离群者排除，未核实在群状态不用于授予操作权限。前置参与命令、模型候选和事务提交使用同一收件人证据。状态schema完整解释工作生命周期，空状态集合明确表示不筛阶段。

### 2. 上下文按本轮读取

`ContextBuilder`只将实际展示／使用的证据放入快照。公开的轻量对象索引用于解析，不自动成为当前话题，也不把其全部来源加入依赖。新目标、原生引用与延续讨论分开；普通问候不带出旧暂停工作。

焦点来自可信决策结果和参与者关系，支持单个或多个对象，不从机器人旧文字猜测。读视图以当前消息的持久顺序为边界；原生引用保留自己的时间，经过控制器证明的同轮派生事件继承其父事件的因果顺序。读取和使用仍核对父来源的可见性与删除状态。

普通任务进度使用任务版本；只有实际消费的任务列表才绑定查询见证。隐私删除、成员／姓名和可见性变更仍使用全局隐私失效，不因性能优化而取消。

### 3. 静默是控制状态与出站屏障

静默命令优先处理，激活时默认不回复。消息顺序屏障阻止旧普通回复在静默、到期或恢复后重新冒出；接收、提交和实际发送前使用同一个策略。模型给出的`directness`不构成唤醒凭证。

后续真实点名、经过回执证明的引用和同一调用者的连续对话可唤醒。其他真人插入会终止隐式延续。已受理后台工作不因静默而取消；其结果保留原授权，自主提醒按静默状态等待。已提交／未知发送只查询原回执，不能当成未发送随意丢弃或重发。

初始回复只有有限的调度优先窗口，不再让任务永久等待一条聊天确认的送达。

前台批处理优先级复用同一可信调用凭证：点名、真实回执引用和未被其他真人打断的连续调用及时受理，不因内容涉及搜索、文件或执行而等待空闲批处理窗口。优先级不授予任何执行权限；普通群内讨论继续使用原有有界批处理，轮询频率保持不变。

### 4. 工具说明与权限分开

语义计划声明需要的能力和图片数量；只有明确数值的简单请求走数量快路，不把“若干”默认为一张。`ToolProfile`按实际可见能力贡献指导，删除始终注入的跨领域长规则。

模型初始只看相关工具，可通过可信目录加载本工作已获授权的其它工具。可见集不扩大权限；角色、功能开关、来源、原授权与新策略仍由网关检查。普通网页／工具数据不能伪造工具加载证据。

### 5. 检索、阅读和审核使用同一份证据

`ResearchSession`按真实查询参数缓存成功结果并合并相同在途请求。命中缓存仍核对权限，保留原观察时间与费用凭证；失败与未知结果不冒充成功。`EvidenceStore`保留有界的完整已收到正文，`web_read`本地按中文相关段或字节范围续读，不为同一正文反复付费抓取。

同一URL／正文优先保留实际抓取的证据等级。生成与审核共用中文相关性投影，结构化引用清单不再复制任意JSON开头。相同候选、文件字节、请求、来源、策略和检查器指纹匹配时复用已通过的语义审核；格式、来源、租约与派送权限仍重查。

最多两条可信公共只读工具并发；顺序预检，先保存调用意图，分别计费并保留部分成功，模型结果保序。写操作、资源型worker和控制工具不进入此并发路径。当前目标机使用Scoped执行器，原生Harness桥接的串行／中断快照限制没有在本轮改写。

控制器编排与实际重型操作使用不同内存准入。2GB目标机上，编排增量64MiB连同转移空间128MiB和宿主预留96MiB共需288MiB；纯联网工作不再等待尚未启动的512MiB子进程。ASR、工具网关与直接文档校验仍在实际工作前核对完整子进程额度，保留忙碌、未确认退出、真实内存压力和cgroup约束。低内存下延后重型操作，不阻塞可进行的检索与文本编排。

## 验收原则

- 混合运行／暂停工作：限定取消不碰运行项；并发版本变化不能扩大对象集合。
- 多人对话、话题切换、复数指代与后续问询使用同一焦点，不重建旧工作。
- 静默落库、零激活确认、旧排队／在途回复不继续发送；已提交结果仍正确核对。
- 同源缓存／重启／明确刷新保持引用、费用和作用域；中文正文尾部可以继续读取。
- 相同证据审核不重复调用模型，候选／策略／来源／检查器变化和隐私撤回必须失效。
- 断言可观测行为、真实数据和状态，不把旧提示词的逐字内容当作产品契约。

离线合成的四次40ms读取在两路并发下为约94ms，原串行为约181ms；这仅是机制实验，不是生产速度保证。实模、微信和共存验收另行记录，不将模拟结果混称线上效果。
