# 0007：群聊对象、执行证据与微信呈现契约

日期：2026-11-17。状态：用户批准实施，本地与真实群验收结果另行记录。

## 问题

执行循环能正确运行工具，不代表每条群消息都应回答，也不保证模型会为交办请求调用工具。实测中，引用另一成员的叙述因正文含 Pot 被当成直接呼叫；明确搜索请求以口头承诺结束；研究报告的 Markdown、全部引用和时间戳又直接进入微信。

## 决策

沿用 ADR0006 的唯一 AgentKernel。增加统一的回合契约和通道输出边界，不增加另一套执行循环。

1. 接入方提供真实的提及、引用发送者和回执证据。提及词与对话对象分开；叙述里出现 Pot 不构成呼叫。共享账号下，账号 ID 不足以证明目标是机器人，机器人原话需匹配原生发送回执。引用自己可作为上下文，引用他人优先按人际对话处理。
2. 小型语义判定声明本轮对象、交流目的、信息依据和需要的动作证据。信息依据区分稳定知识、已有上下文、需公开查证和用户独有输入，不用产品名或动词词表推断；公开查证只在现有角色及功能授权内成为任务。它不授予角色、工具或成功状态。普通闲聊使用短句与相关上下文，不自动注入旧任务播报；背景事件可以继续保存而不产生可见回复。
3. 同一模型—工具图结束前检查交办义务与真实主机回执。前台完成定义是正确受理，后台完成定义是执行、验证与交付；成功受理可以自然说明开始处理，不能声称已取得尚不存在的结果。凭据匹配后只修正正文并隐藏已满足的变更工具；缺少/不匹配证据时才修复动作。实际目标错误时，通过既有 update_work 事务提交同一工作的完整修正计划，绑定原回执目标版本与本轮所有权，不能覆盖后续真人修改或取消。无进展以持久效果身份判断，不以文案、时间戳或工具提案充数；持久让出后沿用原回执恢复，不新增执行循环、累计 token/金额/步骤预算或重复批准。真正的权限限制或必要输入缺失才能说明阻碍。
4. 前台、后台及提醒共用群聊表达策略：默认简短自然，用户要求细节时展开；无需后续信息则直接结束。研究来源、访问时间与验证证据内部保留，默认不变成群聊中的完整文献清单。显示的链接和时间仍须有真实来源。
5. 所有文本经过同一微信呈现器，再加身份标识和分片。Markdown 解析为纯文本，保留链接、代码和文字内容；文件原件不受影响。

## 数据、恢复与旧消息

迁移016仅为 ga_delivery_parts 增加可空 rendered_text，不回填、不改旧键、哈希或回执。新分片保存实际将发送的文字，重试使用原冻结内容；旧分片仅在原始配方可精确还原时继续，未知原生效果不得重发。来源到期、撤回或忘记时，冻结文本也必须清理，回执身份保留。

维护先使用已运行旧版本完成规范清理、备份及验证，再由候选执行迁移和交接。保持单一发送者、原群数据、账本、2GB资源档和小游戏。授权模式与既有明确静默策略保持；静默下含糊的非直接呼叫不扩大为新唤醒权限。

## 验证

实际聊天只存受控运行目录。回归使用脱敏重构的多成员完整对话，覆盖闲聊、引用他人、引用自己、共享账号提及、首次搜索交办、后续追问、检索结果呈现与机器人回声；明确区分脚本模型和真实 DeepSeek。

须保留旧源码行为断言失败、新源码通过证据；另验冻结分片恢复、未知回执、旧版兼容和新明文副本的隐私清理。只运行必要真实模型/微信群样例，不重复无关多模态矩阵。
