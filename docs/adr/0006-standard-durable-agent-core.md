# 0006：统一的标准 Agent Loop 与持久目标调度

日期：2026-11-17。状态：已实现，通过本地任务、故障恢复与 `test_2` 功能及共存验收；10 秒首次回复指标尚未通过，见[验收记录](../development/DURABLE_CORE_VALIDATION.zh-CN.md)。

本决策替代 ADR 0001 的执行器候选、ADR 0002 的 scoped/Harness 选择，以及 ADR 0005 的固定任务查询回复。身份、来源可见性、权限、单发送者、文件验证和原生交付事实继续有效。

## 问题与需求

- EXEC-CORE-001：取消自写模型—工具循环与 Harness 外围重复控制，前后台使用同一个标准循环实现。
- EXEC-LIVE-001：每个未完成目标必须有执行租约、持久排队/唤醒条件，或真实的输入依赖；普通工具失败不得成为无人负责的暂停。
- CHAT-FACT-002：任务事实通过工具提供，回答依据当前问题自然生成；不得用固定状态模板全面替换模型回答。
- EXEC-EFFECT-002：工具执行结果、外部效果确定性、任务调度是独立概念。缺少草稿输出与外部发送回执丢失不能使用同一种恢复政策。
- OPS-MIGRATE-001：保留既有成员、消息、任务、文件及效果记录；旧配置和检查点可受控读取。迁移期间同一群只有一个生产发送者。
- OPS-2GB-002：前台优先，重型工具单并发、按实测内存准入，保留小游戏所需空间；不增加独立工作流服务器。

用户已取消金额、token 与整个目标的累计步数预算。继续记录费用和用量；单次工具超时、内存隔离、上下文窗口及异常退避不是目标累计预算，不得转成不可恢复的目标终止。

## 决策

采用锁定版本 LangChain `create_agent` + LangGraph，复用现有 Python、ModelPort、PostgreSQL、工具网关、ArtifactStore 和微信适配器。

- 一个共享 `AgentKernel` 封装标准循环；前台群会话与后台任务会话上下文分开。
- 模型桥接只转换消息、工具定义和用量；不自行实现另一套工具循环。
- 产品业务状态仍由事务接口写入，模型不能直接操作数据库或生产 Shell。
- LangGraph 检查点的调度/待执行写入状态与既有引擎检查点一起持久化；恢复不能只拼接消息后从头执行。
- 外围 Supervisor 负责目标租约、资源准入、成果验收与交付，不再次规划模型的每一步。
- 一次模型轮次或一次运行结束不等于目标完成；成果验证和当前目标版本的微信接受回执是业务完成证据。
- 前台业务工具在独立事务中提交并返回回执，模型随后生成回复；数据库事务不能跨越模型联网调用。工具调用重放必须复用已提交回执。
- 保存数据来源与隐私撤回依赖。新检查点和工具事实不能绕过原来源可见性。
- 禁用运行内核的自动外部 tracing；运行证据保存在本地受控记录中。

## 故障与恢复

| 情况 | 负责方与行为 |
| --- | --- |
| 参数、脚本、缺少声明输出等可修复错误 | 工具返回结构化观察及安全诊断，模型在同一循环修复 |
| 暂时网络/服务故障 | 单一重试责任方退避；需要让出时保存状态并持久重排队 |
| 资源不足或 activation 让出 | 只结束本次运行，目标仍待执行；无需真人发送“继续” |
| 草稿工作失败且已证明无发布效果 | 依托隔离/发布证据恢复；不靠文件名关键词或错误名白名单推测 |
| 外部写入回执未知 | 保留原幂等键，持久安排核对；没有证明前不得盲目重复写入 |
| 明确的用户取消或手动暂停 | 保持终止/手动暂停语义，恢复扫描不能擅自重新启动 |
| 缺少必须由用户提供的资料 | 明确具体输入依赖，避免循环索取“确认” |

同工具、同参数、同观察且没有新增产物的重复，属于无进展证据。先向模型提供纠正观察或调整策略，再退避；不能靠不断重新排队同一段执行制造假恢复。

正常资源切片使用 LangGraph drain/检查点续跑。框架单次 recursion 保护不是整个 Goal 的累计步数预算，也不能通过设置 `None` 假装无限。恢复调用继续同一图和最新检查点，不伪造一条用户“继续”消息。

## 保留与退出

保留：微信身份/回声去重、成员群昵称、PostgreSQL 事务与租约、计费账本、文件来源与版本、沙箱、资源治理、定时规则、隐私删除和原生交付队列。

退出：自写 ScopedToolEngine 循环、Harness 子进程循环作为可选择生产路径、前台 Decision-JSON-first 协议、任务查询固定回复覆盖，以及重复的外围模型修补规划。旧导入名如为兼容保留，只能指向同一个新实现，不能保留第二条执行路径。

配置里的旧 `scoped`/`harness` 值迁移为唯一 `langgraph` 值；保留旧配置读取并不代表仍能启用旧执行器。旧检查点保留原始证据，新后端恢复必须检查可恢复性。

## 迁移与发布门槛

1. 新分支实现并验证标准内核、任务恢复、前台工具会话，不改变线上状态。
2. 本地真实 PostgreSQL + 隔离 worker 验证完整任务和故障注入；真实模型验证语言交互与实际产物，区分合成与实模证据。
3. 验证旧数据读取、检查点兼容和安全的恢复/回退，不删除旧任务解除阻塞。
4. 验证前台响应与重型任务共存，真实资源压力下目标让出后能自行续跑。
5. 固定源码/依赖/镜像，完成备份和单发送者切换后才更新 `test_2`；保留回退入口并核对小游戏进程与资源。

必须覆盖：图文 PDF 缺失草稿输出后修复交付；公开图片检索与 Word；多轮话题切换后任务追问/解释/核对；工作进程退出和控制进程重启；发送回执未知去重；限定取消；静默；同账号回声；2GB 资源退避。仅单位测试数量或模型自报完成不作为验收。
