# 0009 由模型选择能力，由工具返回事实

日期 2026-11-18。实施分支 `refactor/pot-capability-contract`。延续 [ADR 0008](0008-model-led-react.md) 的共享 AgentKernel。

`test_2` 的相对提醒失败可以在旧提交稳定复现。合成回放以北京时间 04:35:22 为锚。旧语法漏掉了“分钟以后”，提交校验随后拒绝正确的 04:40:22。聊天历史还同时显示本地时钟和 UTC 消息时刻，造成时间解释错误。

前台上下文从当前消息、原生引用、近期时间线和可见工作预览构造。工作预览展示目标和状态，附件用法由可核对的输入引用授权。可见资源的加载状态与空结果有不同含义。模型可以查询当前成员、分工、计划、记忆、文件和工具回执，再根据这些事实决定下一步。名单可以经工具明确请求更新，单项工作操作在存在多个候选时须绑定真人引用。历史和当前消息的展示采用同一群时区。原始时刻、群内身份、回执和权限来自主机。

模型可提交 `after` 原数值和单位、`wall` 本地日期时间、`shift` 有符号偏移或既有的绝对与周期规则。相对时间由主机精确换算。`clock` 仅修改既有周期规则的钟点。调度器在持久事务中读取消息锚点、选定时区和规则的当前版本，转换为现有的存储模型。相对目标以事件发生时刻为锚。已错过的请求保留原始时间并返回明确结果。准备好的提醒直接进入发件队列，到点才开始的工作由 AgentKernel 处理。计划查询返回本地时刻、发生记录和实际平台发送阶段。旧版本可读取已规范化的持久规则。

模型可以在一轮内回复，或在发起单项动作时选择提交成功后直接确认。需要操作时，工具结果提供明确的阶段和必要的修复信息。提交确认由真实回执产生。轻量公开检索与取页共用一个短时间窗口，并与后台途径共用请求模型、公开 URL 校验和用量记账。长任务通过原有工作记录、检查点和资源治理续跑。运营诊断记录工具错误、回执阶段和投递证据。

模型适配器收到明确的 HTTP 429 限流拒绝时，账本记录并释放这次本地调用预留。恢复绑定同一工作和预留记录。失去响应的请求继续按费用待核对处理。限流状态含义见 2026-11-18 核对的 [DeepSeek API 错误码](https://api-docs.deepseek.com/quick_start/error_codes/)。

独立工作真实入队后，持久事务可同时记录一条受理回执。回执绑定原消息、实际工作和投递编号。模型可选择即时受理，或延后将受理和独立答案合成一次投递。继续一项已经在处理的工作会返回当前可核对状态，原目标保持同一版本。作品验收读取已选定版本的实际字节与验证证据。嵌入的已核验公开图片使用各自的来源记录。来源确定拒绝后，图片工具返回本次工作已经检索到的其他来源，模型可选择继续验证这些页面。

定时写入绑定当前真人操作要求的原文。状态查询读取既有规则、发生记录和平台接受回执。本地时刻预览按选定时区返回日期、时钟和偏移。对于最终交付的 Word，存档的公开图片来源以实际嵌入字节和当前工作范围挂接，支持从工作区捕获的文件。

验收以 25 个反馈用例为发布门槛。回放覆盖可核验的状态、真实隔离 PostgreSQL、适用的容器和故障场景。独立留出的场景另用真实模型和适用的工具检查，绑定源码、用例版本和结果。两层验收使用同一个不可变镜像，并核对隔离解释器实际加载的源码和执行入口。关键案例以工具、产物和交付证据验收。待复核、失败和跳过均阻断测试群切换。
