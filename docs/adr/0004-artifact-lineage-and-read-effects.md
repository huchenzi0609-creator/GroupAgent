# 0004：图像来源血缘与读取效果

日期：2026-11-16。状态：实现与测试群验收中。

## 问题

公开图片被下载为JPEG后，指定PNG交付要求迫使执行器自行转换并从工作区重新导入。该通用途径将产物标成generated，原始下载证据没有形成可验证的父子关系；校验器用同一句话表达来源、数量、重复和格式不足。模型据此反复换图或要求用户确认已经明确的交付方式。

另一个边界将需要付费的图片理解视为外部业务写入。超过单次视图数量的参数失败被记为UNKNOWN，执行器因此无法安全继续。费用是否确定和是否可能重复对外业务效果是不同事实。

## 决策

- 检查、OCR和转写使用现有只读工具契约；失败保留费用状态，但不伪装成未知外部业务写入。实际未停止的处理器继续隔离，未知写操作仍不能重放。
- 图片理解按供应商视图和编码大小限制串行分批，保持全局输入索引、逐批回执和真实完成范围；后一批失败返回真实部分结果，不声称供应商做过未发生的跨批全局比较。
- `image_convert`在隔离解码器中执行转换，并由宿主记录不可由模型补写的父版本、输入／输出字节与像素绑定。原下载证据保持原貌，不把生成后的PNG声称为网络原样下载。
- 校验按原始公开来源去重，并逐项检查请求格式；同一图的两种编码不能充当两张图。失败返回具体缺失约束和可复用产物，修复已有结果无需再次征求相同格式确认。
- 共享子产物的父链只作内部依赖校验，不额外授予私有父版本的直接读取权限；撤回、删除、成员变化和字节篡改仍使派生产物失效。
- 历史UNKNOWN读取只能通过当前实际注册信息、原始调用指纹、回执、账本和工具消息的完整一致证据协调恢复；宿主必须先确认旧执行进程已结束。保留原检查点、累计用量与未知费用，不能直接修改安全标志。

## 验证

任务族 `public_image_workflow` 与版本化数据集覆盖两张／五张JPEG到PNG交付、4+1有界检查、部分失败和剩余输入、不同编码去重、缺失格式诊断、跨工作引用、撤回和历史读取恢复。测试内容与运行方法见 [回归集](../development/PUBLIC_IMAGE_WORKFLOWS.zh-CN.md)。合成内联解码器、模拟供应商及数据库结果与真实隔离／微信送达证据分别记录。
