# ADR 0001 独立控制层与可替换执行器

日期：2026年11月13日

状态：Proposed，作为v0.1 Draft的架构基线；具体运行时选型待验证。

## 问题

旧机器人把群消息接入、有限动作分类、摘要、任务数据库和发送串在同步路径中。新产品需要自然参与、长期工作、媒体和文件交付；依赖单个模型会话既无法独立定义业务完成，也难以处理多人、权限和故障恢复。

## 决策

使用模块化控制层管理群事件、身份、参与、TeamTask、WorkOrder、记忆、调度、预算和交付。通过本项目定义的EnginePort接入执行器，优先验证DeepSeek Harness SDK／插件组合。worker与微信接入凭证隔离，业务状态不依赖执行器私有会话格式。

正式业务存储遵循PostgreSQL事务与租约契约。文件在ArtifactStore独立版本化。先使用数据库队列和单重型worker，不默认引入Redis、独立向量服务、大量微服务或多Agent团队。

## 原因与代价

- 可以复用执行循环而保持产品权限、完成定义和迁移能力可控。
- 长任务不阻塞群对话；换模型／框架时无需重建成员身份与任务事实。
- 明确区分人类分工、Agent目标、执行尝试和时间规则。
- 代价是需要维护适配器、事件契约与独立工具网关，不能仅靠修改一个系统提示。

## 替代方案

- 继续扩展旧分类器：适合少量固定动作，不能作为本规格的通用执行底座。
- 深fork整个Harness产品：控制力强，但维护面较大；先用公开扩展接口，只有明确阻塞才另立ADR。
- 其他持久执行框架：保留备选；替换必须通过同一EnginePort、工具和恢复契约测试。

## 重新评估条件

如果POC发现所选Harness无法满足隔离、取消、恢复、媒体输入或预算控制，先记录证据，再更换组合或执行器。不得为了继续使用某个框架而取消权限与交付约束。

视频识别不在当前计划；本ADR不为它预设实现依赖。依据见[研究报告](../PRE_SPEC_REPORT.zh-CN.md)及[技术契约](../spec/TECHNICAL_CONTRACTS_V0.1.md)。
