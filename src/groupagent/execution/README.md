# Durable execution core

`AgentKernel` builds the only model/tools loop with LangChain `create_agent` and its standard LangGraph `ToolNode`. `LangGraphEngine` supplies the EnginePort lifecycle, scoped gateway, metering and durable callbacks. Foreground conversation uses the same kernel. `ScopedToolEngine` is a source import alias to `LangGraphEngine`; it has no separate implementation. `HarnessEngine` rejects construction, and the native SDK worker/relay have been removed.

A model answer is a `CANDIDATE`. The control plane still verifies the accepted goal, actual artifacts, revisions and delivery receipts before completing business work. Definite tool/schema/output-contract failures are observations in the standard graph. Missing evidence, empty/malformed/truncated replies and unknown/inactive/ungranted tool proposals share one structured repair-feedback path back to its model node. A tool batch with any unavailable proposal executes no peers and cannot widen the host grant; an authorized catalog can expose already granted tools. Actual gateway policy/source revocation remains a host fence. Genuine unknown external effects stop for host reconciliation.

## Checkpoint and restart contract

The version-1 `EngineCheckpoint` envelope remains readable. It retains request/scope, revisions, pending/accepted inputs, receipts, gateway idempotency ledger and cumulative usage. A safe legacy scoped checkpoint is imported into the standard graph; an incomplete tool proposal starts at `ToolNode` without another inference. Native Harness session archives remain preserved data and require explicit offline conversion; no code executes them.

`backend_state.engine` and `execution_backend` are `langgraph`. `backend_state.langgraph` version 1 contains the real LangGraph checkpoint (channel values/versions and scheduler state), metadata and pending task writes, encoded with the pinned typed serializer. It is not a messages-only reconstruction. `durability="sync"` and the existing checkpoint sink persist the boundary before the next node. Gateway intent persistence also completes before any handler starts. Without a supplied sink, the engine remains an in-memory test component; it does not claim process durability.

The saver retains at most the latest checkpoint and immediate parent in memory, and only their referenced blobs/writes. The graph message channel is compacted; full tool receipts and the gateway ledger remain authoritative outside model context. If detailed archive metadata grows, a bounded digest manifest replaces older closed exchanges. Protected authority and open tool exchanges remain exact.

Only a wholly trusted, concurrency-safe public-read batch may use two handler slots. A batch containing an effectful, local, unflagged or worker-admitted tool is serial. Host admission preserves source order, even if framework middleware tasks start in another order. ToolNode owns the actual tool/model scheduling and result ordering.

## Yield, cancellation and metering

Each activation gets a fresh `RunControl`. Activation limits and repeated unchanged observations request cooperative drain; `PAUSED/activation_yielded` means durable requeue, not a user pause or Goal termination. There are no default cumulative token/round/tool/time caps. Explicit finite compatibility configurations remain readable. Input-token estimates meter reservations; exceeding an estimate cannot stop unlimited work. Per-call resource bounds remain.

One repair detector normalizes invalid responses independently of tool call IDs and usage, retaining only sixteen hashes. Three unchanged repairs request drain; after restart another unchanged response drains after one call, so the control plane can back off without discarding the Goal. Changed replies can recover. The graph replaces its immediately preceding exact host feedback at the same revision, keeping repeated repair context bounded and preserving accepted user inputs.

Cancellation reaches model and tool tasks. A late or uncooperative task blocks overlapping execution. Changed input revisions invalidate stale proposals, including after restart. Real `UNKNOWN` receipts or ledger entries cannot be resumed until the trusted reconciler records evidence.

Model reservations and actual/unknown settlements remain metered. A settlement outage records `pending_model_settlement` (reservation, usage and returned reply) before stopping. Only `accounting_recovery_checkpoint` can authorize that narrow accounting-only recovery path: the inference must be quiescent or freshly fenced, and no business effect may be pending or unknown. After ledger recovery, the normal pending model node reuses the retained reply without another provider request. Recoverable ledger adapters implement `recover(request, reservation_id, usage)` with fresh ownership checks and idempotent settlement. Unknown usage is never refunded by assumption.

A recoverable ledger supplies `recovery_key` so `inflight_model_reservation` journals the exact key before admission; the actual reservation ID replaces it before provider dispatch. This covers crashes before reserve, between reserve/begin and after admission. The host retains the original checkpoint and claims a fresh database lease/token before `reconcile_fenced_inference_checkpoint`; all old-controller gateway actions must validate the revoked token. The old HTTP request may still finish, so the marker says `model_call_fenced`, not physically stopped. `reconcile_quiesced_inference_checkpoint` additionally records actual quiescence. Neither path adjudicates a pending/unknown tool, calls a provider or changes usage/ledger amounts. A ledger confirms absent or unstarted keyed reservations before releasing them; it retains uncertain provider charges.

LangSmith tracing is explicitly disabled around kernel execution, irrespective of inherited environment settings. Business events/checkpoints still use the local host callbacks.

## Evidence and upstream references

Inspected and tested on 2026-11-17 with `langchain==1.5.0`, `langgraph==1.2.22`, `langchain-core==1.8.1`, `langgraph-checkpoint==4.3.2`; exact dependency artifacts are recorded in `uv.lock`. The adapter uses the pinned package implementation of `InMemorySaver` for typed serialization and pruning; upgrades require rerunning checkpoint compatibility tests.

- [LangChain agent factory](https://docs.langchain.com/oss/python/langchain/agents) and [custom middleware](https://docs.langchain.com/oss/python/langchain/middleware/custom): model/tool routing and host hook state updates.
- [LangGraph durability modes](https://reference.langchain.com/python/langgraph/pregel/main/Pregel/invoke): synchronous persistence before the next step.
- [RunControl](https://reference.langchain.com/python/langgraph/runtime/RunControl) and [GraphDrained](https://reference.langchain.com/python/langgraph/errors/GraphDrained): cooperative drain at saved superstep boundaries. The online reference can display a different patch version; the installed 1.2.22 API was inspected and exercised locally.

`tests/execution/test_langgraph_core.py` runs real LangChain/LangGraph with explicitly scripted offline ModelPorts. It covers complete file creation/inspection after missing-output feedback, restart before/after tool effects, accepted input during restart, host validation/reconciliation edits, unknown-effect fencing, sink failure, cancellation, unlimited usage estimates and bounded multi-activation recovery. Existing gateway, scope, metering, model recovery, request-input, public-read concurrency and supervisor tests remain active. Native Harness-only tests were retired with their removed runtime; one rejection test ensures it cannot launch. These deterministic tests are not paid-provider, production-group or native-client acceptance.
